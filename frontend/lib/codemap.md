# frontend/lib
## Responsibility
Stateless utilities, the typed backend client, storage/migration helpers, and parsers/exporters. `api-client.ts` is the only typed egress to the Python backend; `backend.ts` is the credentials-aware fetch layer; `project-storage.ts` persists projects to `localStorage`; `timeline-import.ts`/`srt.ts` parse and emit NLE/subtitle formats; `video-generation-model-specs.ts` resolves model/resolution/fps/duration compatibility; the rest are small leaf utilities.

## Design Patterns
- **Single typed backend egress (`api-client.ts`):** `makeEndpointClient(endpoint, method, {exactErrorStatuses, admin})` factory produces functions returning `EndpointResult<TPath, TMethod, TExactStatuses>` — a discriminated union of `{ok:true, data}` | per-status error members (`ExactErrorMembers`) | fallback error members (`'4XX'|'5XX'|'default'`). Path/query params are expanded manually (`patchModelProfile`, `getModelDownloadProgress`, `getAdapterStatus`); admin endpoints route to `backendAdminFetch`.
- **Two fetch transports (`backend.ts`):** `backendFetch` (direct `fetch` with cached `Bearer` token from `window.electronAPI.getBackend()`) and `backendAdminFetch` (proxied through `window.electronAPI.backendAdminRequest`, Response reconstructed). `resetBackendCredentials()` invalidates the cache on backend restart.
- **Result normalization in `requestEndpointResult`:** catches fetch throws → synthetic `NETWORK_ERROR`; handles empty success → `EMPTY_SUCCESS_RESPONSE`; invalid JSON → `INVALID_SUCCESS_RESPONSE`; `resolveErrorStatus` prefers an exact configured status else `resolveFallbackStatus`.
- **Migration separation of concerns:** document-shape migrations live in `types/project-model.ts` (`migrateProjectData`/`normalizeProject`); storage-layout migration (legacy `ltx-projects` array → per-id keys) lives in `hooks/useProjectReferencesMigration` (operated by `project-storage-devtools.ts` rollback); asset-metadata backfill lives in `project-asset-metadata-migration.ts`.
- **Async-generator migration with progress** (`runVisualAssetMetadataMigration`): yields `{kind:'progress',total,completed}` then `{kind:'complete',...,updates}`.
- **Pure parsers** (`srt.ts`, `timeline-import.ts`, `file-url.ts`, `utils.ts`): no IO, easily testable.
- **OpenAPI façades** (`model-profile.ts` in `types/`, `video-generation-model-specs.ts`): derive app types from `generated/backend-openapi`.

## Data & Control Flow
- **Backend HTTP:** components/hooks → `ApiClient.*` → `makeEndpointClient` → `requestEndpointResult` → `backendFetch`/`backendAdminFetch` → `window.electronAPI.getBackend()`/`backendAdminRequest`.
- **Asset import → keep-primary + proxy:** `timeline-import.parseTimelineXml` produces `ParsedTimeline` with local `ParsedMediaRef.path`s → caller passes those paths through `asset-copy.addVisualAssetToProject(srcPath, projectId, 'video'|'image', proxyPath?, onProgress?)` → `window.electronAPI.addVisualAssetToProject`. The original MOV/project primary remains authoritative and is copied verbatim; an MP4 proxy is a sidecar for browser playback and proxy audio only. Thumbnails/dimensions use the proxy when supplied. `addGenericAssetToProject` (audio) skips video processing.
  - `asset-copy.ts::addVisualAssetToProject` now accepts an optional `proxyPath` and `onProgress(fraction, label)`: it subscribes to `window.electronAPI.onAssetImportProgress` filtered to a per-call `jobId`, forwards a normalized `0..1` fraction + phase label to `onProgress` (auto-unsubscribing on completion/failure), and returns `ProjectAssetCopyResult` carrying the optional `proxyPath`. `Asset`/`AssetTake` schemas in `types/project-model.ts` carry optional `proxyPath`; playback resolves `proxyPath ?? path`.
- **Project persistence:** `ProjectContext` → `project-storage.writeProject` (`projectSchema.parse({...project, id})` → `localStorage['ltx-project-<id>']`) and `readProject` (runs `migrateProjectData`, re-writes if `migrated || id corrected`) / `readProjectIds`/`writeProjectIds` (`localStorage['ltx-project-ids']`).
- **Devtools rollback:** `installProjectStorageDevtools()` (DEV-only via `import.meta.env.DEV`) exposes `window.__ltxProjectStorageDebug.rollbackProjectReferencesMigration` which reverses per-id storage back to the legacy `ltx-projects` array.
- **Asset metadata backfill:** `runVisualAssetMetadataMigration(assets, electronAPI)` collects per-path jobs (deduped across asset + its `takes`), calls `makeThumbnailsForProjectAsset`/`makeDimensionsForProjectAsset` as needed, emits a `complete` event with per-asset `Partial<Asset>` patches (including rewritten `takes[]`).
- **Model-spec resolution (`video-generation-model-specs.ts`):** `resolveVideoGenerationOptions` cascades compatibility model→resolution→fps→duration using `getResolutionMap` (selects `a2v_supported_resolutions_durations` when `hasAudio` else `supported_resolutions_durations`), honors `minimumDuration`, and via `chooseOption` preserves the current selection or falls back to the first valid option; `sanitizeVideoGenerationSettings` returns `null` when nothing is compatible and forces `aspectRatio` to `'16:9'`/`'9:16'`; `getVideoGenerationModelSpecs` picks `api_models` vs `local_models`.
- **Media playback:** `file-url.pathToFileUrl` → `<video src>` / `<img src>` (native `file://`; Windows drive-letter colon preserved; segments `encodeURIComponent`-encoded).
- **Logging:** `logger.*` → `console` + best-effort `window.electronAPI.writeLog({level, message})`.
- **Keyboard shortcuts:** `keyboard-shortcuts.ts` exposes `ACTION_REGISTRY`, four built-in layouts (`LTX_DEFAULT_LAYOUT`, `PREMIERE_LAYOUT`, `DAVINCI_LAYOUT`, `AVID_LAYOUT`) → `BUILT_IN_PRESETS`, plus `formatKeyCombo`, `eventMatchesCombo` (Mac Option-key uses `e.code` via `codeToKey`), `resolveAction`, `findConflicts`, `cloneLayout`.

## Integration Points
- **`generated/backend-openapi`:** `paths` and `components['schemas']` drive `api-client.ts`, `video-generation-model-specs.ts`, and (via `types/model-profile.ts`) the model-profile/adapter hooks.
- **`shared/electron-api-schema`:** `ElectronAPI` type pins `project-asset-metadata-migration.ts` to `Pick<ElectronAPI, 'makeThumbnailsForProjectAsset' | 'makeDimensionsForProjectAsset'>`.
- **`window.electronAPI` (preload bridge):** `getBackend`, `backendAdminRequest`, `writeLog`, `addVisualAssetToProject`, `addGenericAssetToProject`, `makeThumbnailsForProjectAsset`, `makeDimensionsForProjectAsset`, `onAssetImportProgress` (progress stream consumed by `asset-copy.ts`).
- **`contexts/ProjectContext`:** consumes `project-storage` (`readProject`/`writeProject`/`readProjectIds`/`writeProjectIds`/`deleteProjectEntry`) and `types/project-model` (`normalizeProject`, `projectSchema`).
- **`hooks/`:** `use-generation` (`api-client`, `generation-errors`, `logger`), `use-model-profiles`/`use-official-adapters`/`use-video-generation-model-specs` (`api-client`), `use-ic-lora`/`use-retake` (`api-client`, `logger`), `use-hf-auth`/`use-hf-model-access` (`api-client`, `logger`), `use-backend` (`backend`, `logger`), `useProjectReferencesMigration` (`project-storage`, `types/project-model`, `logger`).
- **`main.tsx`:** imports `installProjectStorageDevtools`.
- **`types/project-model` & `types/project.ts`:** schemas/types and `EFFECT_DEFINITIONS`/`TEXT_PRESETS` catalogs consumed across views/components.
- **`electron/ipc/file-handlers.ts`:** implements `addVisualAssetToProject`/`addGenericAssetToProject`/`makeThumbnailsForProjectAsset`/`makeDimensionsForProjectAsset`/`transcodeVideoForPreview`; `proxyPath` is a keep-primary sidecar (see Data & Control Flow).
