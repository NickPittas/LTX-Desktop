# backend/services/

## Responsibility

Root of the service layer. Holds the cross-cutting primitives every pipeline/service subpackage shares:

- `interfaces.py` — single import location for all service `Protocol` types and DTOs (the dependency-inversion boundary).
- `__init__.py` — package marker only; callers import service Protocols directly from `services.interfaces`.
- `services_utils.py` — shared type aliases, device helpers, and structural `Protocol`s used across services.
- `ltx_components.py` — pure resolver turning a `ModelProfilePayload` into a typed `ResolvedLtxComponents` bundle (no heavy imports; GPU-free/testable).
- `base_video_model_registry.py` — **unified source of truth for generation-selectable base video transformer variants** (`BaseVideoModelRegistryEntry`, `iter_base_video_model_entries`, `resolve_base_video_model_selection`). Drives `GET /api/models/model-options`, the scanner's Kijai/QuantStack artifact recognition, the request resolver, and the family-mismatch guard. `ModelSelectionID` is a runtime `str`; unknown ids raise `KeyError` (handlers translate to `UNSUPPORTED_MODEL_SELECTION`).
- `ltx_pipeline_common.py` — shared LTX pipeline helpers, including `encode_video_output()` and the app-owned 768/256 spatial tiling overlap shared-path seam mitigation (80/24 temporal); retake and HDR use separate policies and are excluded. Wraps `encode_video_output` in `memory_trace.phase("encode_video_output")` (observational; no-op when trace disabled).
- `memory_trace.py` — process-wide JSONL memory profiler for memory-strategy diagnostics. Env-gated on `LTX_MEMORY_TRACE_PATH`: when absent **every** entry point is a full no-op (no torch/psutil import, no file write, null context manager) so the hot request/generation path is untouched. When set, lazily imports `torch`/`psutil` inside `_read_stats()` only, and appends one JSON line per event carrying the memory fields + caller extras under a write lock. Surface: `is_enabled()`, `MemoryTraceContext`/`current_context()`/`use_context()`/`run_with_context()` (run_id+case_id, inherited via `ContextVar`), `write_event()`, `snapshot()` (`MemorySnapshot`), `reset_peak()`, `phase()` context manager (`phase_start`/`phase_end`/`phase_error`). Failures in sampling/serialization are always swallowed — tracing can never raise into the request or generation path.
- `block_offload.py` — block-level CPU↔onload-device offload for transformer stages: groups a transformer's nested block list and wires per-group forward hooks. Combines **static GPU residency** (first N blocks live on the onload device, unhooked) with **rolling blockswap** (offloaded groups prefetched CPU→onload on a side CUDA stream ahead of use and evicted after use, with a configurable look-ahead/look-behind window). Residency/prefetch/look-behind come from a runtime VRAM/frame-count policy with env overrides; `release_block_offload_residency(model)` is the primitive to drop all block GPU residency for a built model. Pairs with `services.local_memory_plan.LocalMemoryPlan` and the `patches/block_offload_patch.py` DiffusionStage build wrapper.
- `workload_policy.py` — pure IC-LoRA workload classifier. V2 in/outpainting plans additionally carry `inpaint_context_window_px`/`inpaint_context_overlap_px`, keyed in the cache and selected from the handler's one effective-VRAM snapshot.

## Design Patterns

- **Interface-first / Protocol-based DI.** Each subpackage defines a `Protocol` (in `<subpkg>/<subpkg>.py`) and a concrete `*Impl`. `interfaces.py` aggregates the Protocols; `app_handler.ServiceBundle` wires real impls (`build_default_service_bundle`), tests wire fakes (`tests/fakes/services.py`). `HTTPClient`, `GpuCleaner`, `GpuInfo`, `ModelDownloader`, etc. are all structural Protocols — duck-typed, no inheritance.
- **Lazy heavy imports.** `ltx_pipeline_common.py` imports `ltx_core.*` / `ltx_pipelines.*` inside helper function bodies (`encode_video_output`, `default_tiling_config`, `default_guiders`, `video_chunks_number`), keeping `services` importable without torch/GPU.
- **TYPE_CHECKING-only type aliases.** `services_utils.py` exposes `TilingConfigType`, `FrameArray`, `AudioType` as `object` at runtime but real types under `TYPE_CHECKING` — avoids importing `ltx_core`/`numpy` at module import.
- **Pure resolver for profile data.** `ltx_components.resolve_components()` is a side-effect-free mapping from `ModelProfilePayload` → `ResolvedLtxComponents`; `cache_key` tuple enables downstream pipeline caching. When a live selection is present, the caller passes explicit `selected_transformer_format` and `selected_base_family` (from the registry entry) so no filename/path-only inference happens for the selected family/format.
- **Unified base-video registry (source of truth).** `base_video_model_registry.iter_base_video_model_entries(models_dir)` enumerates every selectable base video variant with read-only filesystem evidence (installed/missing/wrong-folder/duplicate). `models_handler.get_model_selection_options()` consumes it; `model_scanner` derives Fast-family Kijai/QuantStack artifacts from its static table; `pipelines_handler._resolve_selection()` resolves a selection id to an entry; `video_generation_handler` reads `pipeline_family` for the family-mismatch guard.

## Data & Control Flow

### Encode path — `encode_video_output()` (EXR/MOV plan focal point)

`ltx_pipeline_common.py:35`:

```python
def encode_video_output(video, audio, fps, output_path, video_chunks_number_value) -> None:
    from ltx_pipelines.utils.media_io import encode_video
    encode_video(video=video, fps=fps, audio=audio, output_path=output_path,
                 video_chunks_number=video_chunks_number_value)
```

- **Inputs:** `video: torch.Tensor | Iterator[torch.Tensor]` (decoded RGB frames straight from the VAE `VideoDecoder` — the PRIMARY generation output, *not* a transcoded MP4); `audio: AudioOrNone`; `fps: int` (cast from request `frame_rate`); `output_path: str` (final `.mp4` path); `video_chunks_number_value: int` (computed via `video_chunks_number()` → `ltx_core.model.video_vae.get_video_chunks_number(num_frames, tiling_config)` — controls VAE chunked decoding, unrelated to encode container).
- **Dims/pixel-format handling:** the wrapper passes *no* dimensions or codec args. `encode_video()` derives H/W from the tensor shape and **hardcodes H.264 / yuv420p** (orchestrator-confirmed bottleneck). **`ltx_pipelines` is an EXTERNAL git dependency** (`Lightricks/LTX-2`, rev `a2c3f240…`, `backend/pyproject.toml:48`), **not vendored in this repo** — so `media_io.encode_video` cannot be edited here. No codec, pixel-format, container, or bit-depth parameter is threaded through this signature.
- **Callers (uniform signature):**
  - `services/fast_video_pipeline/ltx_fast_video_pipeline.py:180` and `:200` (fps=8 fallback path)
  - `services/a2v_pipeline/ltx_a2v_pipeline.py:172`
  - `services/ic_lora_pipeline/ltx_ic_lora_pipeline.py:436` and `:830`
  - `services/retake_pipeline/ltx_retake_pipeline.py:361` calls `encode_video(...)` **directly** (bypasses the wrapper) with the same 5 kwargs — must be updated in lockstep with any encode-path change.
- **EXR/MOV implication:** the decoded-frame tensor/iterator is the natural ProRes/EXR input. Because `ltx_pipelines` is an external (non-vendored) dependency, the correct interception point is **this wrapper** (`encode_video_output`) — branch to a new encoder service (ProRes via `ffmpeg` subprocess, EXR via a writer) using the decoded-frame tensor *before* the `encode_video` import/call, rather than editing `media_io` itself. The direct retake call must be re-routed through the same new encoder.

### Source-video colorspace invariant (CM-2)

All source-video workflows (retake, IC-LoRA V2V standard/inpaint/union) decode through `services.exr_input.iter_video_frames_to_model_domain` before model/VAE input so a tagged non-Rec.709 source (BT.601 / Rec.2020 / ...) is transferred to the Rec.709 model domain (untagged/bt709 is byte-identical passthrough); their handlers also run `detect_colorspace(...)` on the source and pass it as `input_colorspace` into the output encoder for ProRes/EXR CS preservation. HDR (`_create_conditionings`) uses the same input transfer before its per-frame `LogC3`/VAE transform, but saves through its own linear EXR writer + SDR proxy (not `encode_video_output`), so it does not consume `input_colorspace`. Ingredients (image-conditioned T2V) has no source video and is unaffected.

### `services_utils.py` device helpers

`get_device_type()` normalizes `str | torch.device | object` → `"cuda"|"mps"|"cpu"`. `device_supports_fp8()` is true only for `cuda`. `sync_device()` and `empty_device_cache()` dispatch to `torch.cuda.*` / `torch.mps.*` with logged fallbacks — consumed by `TorchCleaner` and pipeline teardown.

## Integration Points

- **`app_handler.py`** — `ServiceBundle` (line 230) types every field against the Protocols imported from `services.interfaces`; `build_default_service_bundle()` instantiates the real `*Impl` classes from subpackages.
- **`ltx_components.resolve_components()`** → consumed by pipeline constructors (fast/a2v/ic-lora/retake) to drive pipeline builder wiring and to key the pipeline cache (`cache_key`).
- **`ltx_pipeline_common.encode_video_output()`** → **the single chokepoint for the EXR/MOV-Primary-Output work.** All four generation pipelines funnel decoded frames through it (retake bypasses via a direct `encode_video` call that must change in tandem). `ltx_pipelines` is an external dependency, so the new ProRes/EXR encoder must be inserted here (before the `encode_video` call), not inside `media_io`.
- **HDR pipeline (`hdr_ic_lora_pipeline/`)** — `LTXHdrIcLoraPipeline(HDRICLoraPipeline)` is the dedicated HDR V2V path. It **does not call upstream `HDRICLoraPipeline.__init__`**; a custom initializer reproduces upstream block wiring (`device`/`dtype`/`_tiled_vae_encode_threshold`/`text_embeddings`/`image_conditioner`/`stage_1`/`stage_2`/`upsampler`/`video_decoder`/`_hdr_config`) with app-resolved LoRAs, quantization, and components, so inherited `__call__`/`_run_stage2_phase`/`_decode_video`/`hdr_transform`/`reference_downscale_factor` remain usable. `create(...)` owns LoRA selection (dev: distilled @ 0.5 then HDR @ 1.0; distilled: HDR @ 1.0 only; `unknown` rejected), quantization/offload policy (GGUF → None + `install_gguf_loader`, GGUF offload forced to NONE; split safetensors w/ video VAE on CUDA → `kijai_fp8_quantization_policy()`, offload owned by the memory plan (Kijai block-offload uses NONE to enter the patched block-offload builder), DISK rejected; monolith on CUDA → `build_policy`), HDR LoRA metadata via `read_hdr_lora_config` (absence → upstream default), and post-build component patching (`install_gguf_loader`/`install_kijai_transformer_config_patch`/`install_gguf_component_paths`). It accepts `checkpoint_path` as a single path (monolith) or tuple (split/Kijai/GGUF). It overrides `__call__` (one-stage: full-res stage-1 sampling → chunked decode, bypassing upstream's upsampler + stage-2; `stage_2`/`upsampler` remain constructed for component-patch compatibility but are never called), `_create_conditionings` (stream decoded source frames into one preallocated tensor + duplicate-final-frame pad to `8n+1`; no decoded/transformed frame lists retained; called once at full aligned res), `_run_stage2_phase` (context-window loop hook + timing — retained but unused by the one-stage `__call__`), and `_decode_video` (decode tiling 768/128 + timing; **chunked** VAE decode + per-chunk HDR `LogC3` postprocess with immediate CPU chunk handoff, replacing upstream's full-video GPU postprocess that OOMed on 201-frame Kijai/GGUF). It writes the linear HDR tensor as a primary EXR sequence via `ltx_pipelines.utils.media_io.save_exr_tensor` (no EOTF/tonemap/clamp) then an SDR proxy via `encode_exr_sequence_to_mp4`. **It does NOT use `encode_video_output`** — HDR is the one pipeline with its own EXR writer.
- **`services/utils` device helpers** → `services/gpu_cleaner/torch_cleaner.py` (`empty_device_cache`), pipeline `__del__`/teardown paths (`sync_device`).
- **Phase 1 observational instrumentation (env-gated)**: the pipelines/handler and pipeline services emit trace events purely for diagnostics — no behavior change when `LTX_MEMORY_TRACE_PATH` is unset. Sites: `pipelines_handler` load/create phases (`pipeline_load:*` / `pipeline_create:*` for video/ic-lora/hdr-ic-lora/a2v/retake) and the GPU-swap eviction (`pipeline_evict:gpu_swap`); `ltx_pipeline_common.encode_video_output` (`phase("encode_video_output")`); `hdr_ic_lora_pipeline` (`hdr_create` / `hdr_conditionings` / `hdr_generate` / `hdr_stage_1|2` builds); `ic_lora_pipeline` manual drains (`manual_drain:ic_lora`); `patches/gguf_loader_fix` GGUF-load events. These are read by `scripts/live_workflow_test.py` to prove trace ownership per case.
- **Adaptive memory/performance policy (HDR-first, intended to generalize)**: `block_offload.py` + the HDR wrapper implement a runtime policy driven by detected CUDA VRAM and padded frame count, not fixed tiers. Resident transformer blocks come from a monotonic piecewise-linear VRAM curve (anchors ≈ 12/16/24/31 GiB → 0/26/37/46 blocks; at ≥31 GiB the resident policy overrides to 48 = all-resident / 0 swapped for ≤121-frame or unknown-frame workloads, keeping the 46/2 swap margin only for >121-frame runs; all IC-LoRA workflows classify their workload via `services.workload_policy.classify_lora_workload` (frame_count/dims/VRAM → `LoraWorkloadPlan`) and fold the plan's `cache_key_parts` into the pipeline cache key + apply plan envs (resident blocks / HDR rolling context / VAE encode tile) before load, so a large run never reuses a normal-run pipeline). Transformer loading strategy (`services.local_memory_plan`) is driven by a per-run VRAM snapshot (`snapshot_vram()`: `total`/`free`/`effective`/`effective_tier`, reserve 2 GiB; `effective = max(0, min(total|free, free−2))`, bucketed to an `effective_vram_tier`). Callers prefer `effective_tier_gib` over total VRAM, and `pipelines_handler` folds `effective_vram_tier=<tier>` (`=unknown` when free VRAM is unavailable) into the pipeline cache key so a high-free-VRAM pipeline is never reused under low free VRAM. Thresholds from measured runs: GGUF uses `gguf_lazy` at ≥24 GiB for both HDR and non-HDR (block offload below 24 GiB / unknown), and Kijai FP8-scaled routes through the **patched** block-offload builder below 40 GiB — upstream `full_resident` OOMs at 31 GiB even though the weights fit, so at 31 GiB normal T2V/I2V/Ingredients/HDR workloads run 48-resident / 0-swapped *inside the patched path* (no blockswap, but not the upstream full-resident path), and true `full_resident` is only returned at ≥40 GiB. Offloaded blocks stream under rolling blockswap (default look-ahead prefetch 2, look-behind 0) on a side CUDA stream with race-free event ordering. In `hdr_ic_lora_pipeline/ltx_hdr_ic_lora_pipeline.py`, encode tiling is chosen by policy from VRAM+padded frames (31GiB: ≤121f no tile, >121f tile512; lower VRAM tiles earlier, with a direct→tiled OOM fallback), decode tiling is fixed at spatial 768/overlap 128 (with chunked decode + per-chunk HDR `LogC3` postprocess and immediate CPU handoff to avoid the full-video GPU postprocess OOM on 201-frame Kijai/GGUF), and resident/lookahead/encode/decode are overridable for benchmarking. Env knobs: `LTX_BLOCK_OFFLOAD_RESIDENT_BLOCKS` (positive overrides residency; ≤0 disables), `LTX_BLOCK_OFFLOAD_PREFETCH_GROUPS`, `LTX_BLOCK_OFFLOAD_LOOKBEHIND_GROUPS`, `LTX_HDR_VAE_TILE_SIZE` / `LTX_HDR_VAE_TILE_THRESHOLD`, `LTX_HDR_DECODE_VAE_TILE_SIZE`, `LTX_HDR_PADDED_FRAMES` (process-local, set by HDR `generate()` around the call). Computed policy values are traced (`block_offload_apply`/`build`, `hdr_encode_policy`). **Rolling temporal context windows are only enabled by default above 121 padded frames** (≤121 padded frames → disabled — `generate()` passes its known `padded_num_frames` to `_hdr_context_config` directly, with `LTX_HDR_PADDED_FRAMES` only as a fallback when no value is passed; `LTX_HDR_CONTEXT_WINDOW=0` also disables) because the one-stage pass fits all-resident at ≤121 frames; above 121 full-res full-frame one-stage OOMs even with all blocks streamed, so defaults are VRAM-based — RTX 5090/31GiB: 65f window / 16 overlap / pyramid (passes Kijai+GGUF 201f with 46 resident / 2 swapped; 73f failed at 46 and 42 resident); ≥24GiB: 49/16; below/unknown: 33/8 (provisional, pending hardware validation). This is HDR-first but is the intended shape for a shared memory/model-management layer reusable by the other generation workflows later.
  For 24–27 GiB 1080p inpaint, the workload policy caps residency at 20 blocks with prefetch 0 to preserve VAE/LoRA/activation headroom.
- **`tests/fakes/services.py`** — fakes implement the Protocols aggregated in `interfaces.py`; `conftest.py` wires a fresh `AppHandler` per test with the fake bundle.
- **Sibling subpackages** (`http_client/`, `gpu_info/`, `gpu_cleaner/`, `model_downloader/`, `patches/`) each own their own Protocol + Impl and are documented in their own `codemap.md`.
